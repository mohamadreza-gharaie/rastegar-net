# راه‌اندازی «رستگار نت» روی Render.com

## پیش از شروع (مهم)
- **پلن رایگان Render مناسب این برنامه نیست.** روی پلن رایگان هر ۱۵ دقیقه بی‌کاری سرویس می‌خوابد و فایل‌های محلی (از جمله دیتابیس کاربران و رمزها) با هر خواب یا راه‌اندازی مجدد پاک می‌شود. برای همین `render.yaml` روی پلن **Starter** و یک **دیسک ۱ گیگابایتی** تنظیم شده است (هزینهٔ ماهانهٔ آن را هنگام ساخت در Render می‌بینید).
- فقط **یک نمونه (instance)** از سرویس اجرا کنید؛ وضعیت کلاس‌ها در حافظه است و با چند نمونه به‌هم می‌ریزد (Render هم روی سرویس دارای دیسک چند نمونه را اجازه نمی‌دهد).

## مرحله ۱ — گذاشتن پروژه در GitHub
Render پروژه را از GitHub می‌گیرد.
1. در [github.com](https://github.com) حساب بسازید (اگر ندارید) و روی **New repository** بزنید.
2. نام مخزن را `rastegar-net` بگذارید، حالت **Private** را انتخاب کنید و **Create repository** را بزنید.
3. گزینهٔ **uploading an existing file** را بزنید.
4. زیپ را باز کنید و **محتوای داخل پوشهٔ `rastegar-net`** را (نه خود پوشه را) بکشید و رها کنید؛ باید `app.py`، `render.yaml`، `requirements.txt` و پوشه‌های `templates` و `static` در ریشهٔ مخزن دیده شوند.
5. **Commit changes** را بزنید.

## مرحله ۲ — ساخت سرویس با Blueprint
1. در [dashboard.render.com](https://dashboard.render.com) وارد شوید (یا ثبت‌نام کنید و حساب GitHub را وصل کنید).
2. بالای صفحه **New +** ← **Blueprint** را بزنید.
3. مخزن `rastegar-net` را انتخاب کنید و **Connect** را بزنید.
4. Render فایل `render.yaml` را می‌خواند. در فرم باز‌شده:
   - برای `ADMIN_PASSWORD` رمز پنل مدیریت را بنویسید (پیش‌نهاد: همان `Rastegar12net21` یا رمز قوی‌تر).
5. **Deploy Blueprint** (یا Apply) را بزنید و صبر کنید تا ساخت تمام شود (چند دقیقه). وقتی وضعیت **Live** شد، آدرس سرویس به‌شکل `https://rastegar-net-xxxx.onrender.com` بالای صفحه است.

## مرحله ۳ — آزمایش
1. آدرس را باز کنید؛ باید صفحهٔ انتخاب کلاس بیاید.
2. `/admin` را باز کنید و با رمز مدیریت وارد شوید.
3. از بخش «کاربران» یک دانش‌آموز آزمایشی اضافه کنید، در یک مرورگر دیگر با او وارد کلاس شوید، و از پنل «ورود به کلاس» معلم را هم وارد کنید.
4. دوربین/میکروفن را روی هر دو دستگاه امتحان کنید.

## اگر Blueprint نخواستید (روش دستی)
**New +** ← **Web Service** ← مخزن را انتخاب کنید، سپس:

| فیلد | مقدار |
|---|---|
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn --worker-class gthread --workers 1 --threads 100 --timeout 120 --bind 0.0.0.0:$PORT app:app` |
| Instance Type | Starter (یا بالاتر) |
| Health Check Path | `/healthz` |

بخش **Environment**: `SECRET_KEY` (یک متن تصادفی بلند)، `ADMIN_PASSWORD`، و `RASTEGAR_DB` = `/var/data/rastegar.db`.
بخش **Disks**: **Add Disk** با Mount Path برابر `/var/data` و اندازهٔ ۱ گیگابایت.

## نکته‌های مهم بعد از راه‌اندازی
- **اتصال تصویر/صدا:** برنامه از سرور STUN گوگل استفاده می‌کند. اگر بعضی دانش‌آموزان تصویر یکدیگر را نمی‌بینند (به‌خصوص با اینترنت موبایل یا شبکه‌هایی که STUN را مسدود می‌کنند)، یک سرور **TURN** لازم است؛ در Render بخش Environment این متغیرها را اضافه کنید: `TURN_URL` (مثل `turn:example.com:3478`)، `TURN_USER`، `TURN_PASS`. می‌توانید `STUN_URLS` را هم با سرور دیگری عوض کنید.
- **دامنهٔ دلخواه:** در Render ← Settings ← Custom Domains دامنه اضافه کنید. اگر دامنه با آدرس `onrender.com` فرق دارد و دچار مشکل اتصال زنده شد، متغیر `CORS_ORIGINS` را برابر `https://دامنهٔ-شما` بگذارید.
- **تغییر رمز مدیریت:** Environment ← `ADMIN_PASSWORD` را عوض کنید و سرویس خودکار دوباره راه‌اندازی می‌شود.
- **به‌روزرسانی برنامه:** فایل‌های تازه را در GitHub آپلود کنید؛ Render خودکار دوباره می‌سازد و داده‌های روی دیسک حفظ می‌شود.
- **پشتیبان:** دیتابیس `/var/data/rastegar.db` است. از بخش Disks می‌توانید Snapshot بگیرید.
- ظرفیت: تماس به‌صورت مستقیم بین مرورگرهاست و برای حدود ۸ تا ۱۲ نفر در هر کلاس مناسب است؛ سرور فقط سیگنال و گفتگو را رد و بدل می‌کند.
